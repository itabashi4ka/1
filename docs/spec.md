# 分割払い計算アプリ（macOS）仕様書

## 1. 概要

分割払いの条件を計算し、患者に見せながら説明できるmacOSアプリ。
計算結果は自作のHTMLテンプレートを使って「支払い表」（PDF／印刷）として出力できる。

### 基本方針
- 年率は既知の入力値。**求めたいのは月額または分割回数、および利息総額**。
- 利息総額は通常**非表示（ブラインド）**にし、必要なときだけ表示する。
- 画面は患者に直接見せるため、見せたい情報だけを大きく表示する。
- 見た目（院名・ロゴ・色・文言など）は、コードを触らず**設定画面／設定ファイル**で変更できる。
- 計算ロジックはUIから分離し、テストで正しさを確認できるようにする。

---

## 2. 変数

| 変数 | 内容 | 備考 |
|---|---|---|
| 支払総額 A | 元本（現金価格、税込） | 円、整数 |
| 年率 | 金利（%） | 0%も許可。既定値を保持する（7.2参照） |
| 分割回数 n | 月々払いの回数 | 1以上の整数 |
| 月額 P | 毎月の支払額 | 円 |
| ボーナス加算額 B | ボーナス月に月額へ上乗せする額 | 任意、0なら無効 |
| ボーナス月 | 上乗せする月（複数選択） | 例: 6月・12月 |
| 初回支払月 | 1回目の支払月 | 支払い表の月表示に使う |
| 患者名 | 支払い表に印字する名前 | 任意、保存しない |

---

## 3. 計算モード

| モード | 入力 | 出力 |
|---|---|---|
| ① 月額から求める | 支払総額、年率、月額（＋ボーナス） | 分割回数、利息総額 |
| ② 回数から求める | 支払総額、年率、分割回数（＋ボーナス） | 月額、利息総額 |

どちらも 利息総額 = 支払い合計額 − 支払総額 で求める。

---

## 4. 計算仕様

### 4.1 前提
- 返済方式は**元利均等**。
- 月利 r = 年率 ÷ 100 ÷ 12（月単位で計算し、日割りは行わない）。
- 端数は**円未満切り捨て**。差額は**最終回で調整**する（設定で変更可能にする）。

### 4.2 ボーナスなし
- モード②（月額を求める）
  - r > 0: P = A × r ÷ (1 − (1 + r)^−n)
  - r = 0: P = A ÷ n
- モード①（回数を求める）
  - r > 0: n = −ln(1 − A × r ÷ P) ÷ ln(1 + r)、小数の場合は切り上げ
  - r = 0: n = A ÷ P、小数の場合は切り上げ
  - 最終回は残高に合わせて調整する

### 4.3 ボーナスあり
公式で直接解けないため、**月ごとの残高シミュレーション**で計算する。

毎月の処理:
1. 利息 = 残高 × r（円未満切り捨て）
2. 支払額 = 月額（ボーナス月は月額 + ボーナス加算額）
3. 元本充当 = 支払額 − 利息
4. 残高 = 残高 − 元本充当

- モード①: 残高が0以下になるまで繰り返し、必要な回数を求める（最終回は残高に合わせて調整）。
- モード②: 「回数ちょうどで残高が0になる月額」を二分法などで探索する（探索範囲は 0 ～ A、収束条件は1円未満）。

### 4.4 完済不能の検出
月額（およびボーナス）が毎月の利息以下で元本が減らない場合は、エラーとして扱う。

---

## 5. 画面仕様

### 5.1 入力エリア
- 計算モード切り替え（① 月額から／② 回数から）
- 支払総額、年率、分割回数（またはボーナスを除く月額）
- ボーナス払い: ON/OFF、加算額、ボーナス月の選択（年2回など、月を指定する形）
- 初回支払月、患者名（任意）

### 5.2 結果エリア（患者に見せる部分）
- 支払い表と同じ形の表で、上から次の順に表示する
  1. 元本（値を太字）
  2. 年率
  3. 分割回数（値を太字・大きく）
  4. 月々のお支払い（値を太字・大きく）
  5. （ボーナス払いがあるときだけ）ボーナス月加算
  6. お支払い期間
  7. お支払い額合計
- 注記文（例:「概算です。実際の条件は契約内容によります」）を画面下部に表示（文言は設定で変更可）

### 5.3 利息総額のブラインド
- 起動時は利息総額を非表示（「●●●円」など）にする。
- 「利息総額を表示」ボタンで表示／再度押して非表示に戻す。
- **入力値を変更して再計算したときは、自動で非表示に戻す**。

### 5.4 スケジュール表
- 回ごとに、支払月、支払額、（ボーナス加算額）、残高を表示
- 元本充当・利息の列は画面には表示しない（支払い表の出力はテンプレートに従う）

---

## 6. 支払い表の出力

### 6.1 方式
- 自作の**HTMLテンプレート**に計算結果を差し込み、PDFとして出力する（印刷にも対応）。
- テンプレートはアプリ側で置き場所を決め（例: 設定フォルダ内の `templates/`）、複数のテンプレートから選べると望ましい。

### 6.2 差し込み項目（プレースホルダー案）

| プレースホルダー | 内容 |
|---|---|
| `{{clinic_name}}` | 院名（設定から） |
| `{{patient_name}}` | 患者名 |
| `{{issue_date}}` | 作成日 |
| `{{principal}}` | 支払総額（元本） |
| `{{annual_rate}}` | 年率 |
| `{{installments}}` | 分割回数 |
| `{{monthly_payment}}` | 月額 |
| `{{bonus_amount}}` | ボーナス加算額 |
| `{{bonus_months}}` | ボーナス月 |
| `{{total_payment}}` | 総支払額 |
| `{{total_interest}}` | 利息総額（出力時に「表示する」を選んだ場合のみ） |
| `{{note}}` | 注記文 |

### 6.3 スケジュール表の繰り返し行
テンプレート内に、1行分のひな形を次のマーカーで囲んで書く。

```html
<!-- ROW_START -->
<tr>
  <td>{{row.no}}</td>
  <td>{{row.month}}</td>
  <td>{{row.payment}}</td>
  <td data-show="interest">{{row.interest}}</td>
  <td>{{row.balance}}</td>
</tr>
<!-- ROW_END -->
```

アプリは、この行を回数分だけ複製して差し込む。

### 6.4 利息の表示／非表示
- 出力時に「利息を表示する／しない」を選べる。
- 「しない」の場合は、`data-show="interest"` を持つ要素をすべて取り除き、`{{total_interest}}` も出力しない。

## 7. 設定・カスタマイズ

- 設定画面で次を変更できる:
  - 院名、ロゴ画像
  - 色（テーマカラー）、フォント、文字サイズ
  - 注記文
  - 端数処理（切り捨て／切り上げ／四捨五入）
  - 使用するHTMLテンプレート
- **既定の年率**を設定に保存する（7.2参照）。
- 設定は1つのファイル（JSON）に保存する。保存先の例: `~/Library/Application Support/<アプリ名>/settings.json`
- 設定のエクスポート／インポートに対応し、別のMacへ同じ設定を移せるようにする。
- 見た目に関する値（色、フォント、文言）は、コード内にベタ書きせず設定から読み込む。

### 7.2 年率の保持
年率は基本的にいつも同じ値を使うため、保持機能を設ける。

- 設定に「既定の年率」を保存し、起動時に年率の入力欄へ自動で入れる。
- 患者ごとの相談などで一時的に別の年率を入力してもよい（その場合、既定値は変わらない）。
- 入力欄の横に「この値を既定にする」ボタンを置き、押したときだけ既定値を更新する。
- 既定値と異なる年率を入力しているときは、画面上で分かるようにする（入力ミスや、前の患者の値の持ち越しを防ぐため）。
- 保存するのは年率などの設定値のみ。患者名や支払総額など、患者に関する入力は保存しない（9章）。

## 8. バリデーション

| 条件 | 対応 |
|---|---|
| 支払総額が0以下 | エラー表示 |
| 年率が0未満、または極端に大きい値 | エラー表示 |
| 年率0% | 利息0円として計算する |
| 分割回数が0以下または整数でない | エラー表示 |
| 月額が毎月の利息以下（完済不能） | エラー表示 |
| ボーナス月が範囲外 | 選択肢を1～12月に限定 |

---

## 9. 個人情報の扱い

- 患者名は支払い表に印字するためだけに使い、**アプリ内に履歴として保存しない**。
- アプリ終了時に、入力内容（患者名を含む）は消える。
- PDFの保存先は出力時にユーザーが選ぶ。

---

## 10. 技術方針

- SwiftUIによるアプリ。**macOSとiPadOSの両対応**（マルチプラットフォーム）とし、計算ロジック・設定・テンプレート処理は共通コードにする。
- 対象OSは、macOSは最新版と直前の1～2バージョン、iPadOSも同程度（要確認）。
- 構成:
  - `Calculator`（計算ロジック、UIに依存しない）
  - `Settings`（設定の読み書き）
  - `Templating`（HTMLテンプレートへの差し込み）
  - `PDFExport`（HTMLからPDF出力・印刷。macOS・iPadOSの両方で動くようにする）
  - `Views`（入力、結果、スケジュール表、設定画面）を小さな部品に分割
- 計算ロジックにはユニットテストを必ず付ける。

---

## 10.5 iPad対応

- macOS版と同じ機能（計算モード、利息のブラインド、支払い表出力、設定）をiPadでも使えるようにする。
- iPad向けの画面配慮:
  - 横向き・縦向きの両方でレイアウトが崩れない
  - 患者に見せる結果表示は大きな文字にする
  - タッチ操作しやすいボタンサイズにする
- 支払い表のPDFは、iPadでは共有シートやAirPrintで保存・印刷できるようにする。
- 設定ファイルとHTMLテンプレートをMacとiPadで共有する方法:
  - 初期は、設定のエクスポート／インポートと、ファイルAppからのテンプレート読み込みで対応する
  - iCloudによる自動同期は、必要になったら追加する（任意）
- 年率の既定値も、同じ設定ファイルに含めて共有する。

## 11. テストケース

計算結果は、表計算のPMT関数などで検算した値をテストに使う。Claude Codeに次の観点で3～5個作らせる。

- 年率あり・ボーナスなし・モード②（例: 100万円、年率3%、36回。月額は約29,081円前後になる想定で、要検算）
- 年率あり・ボーナスなし・モード①（②の結果を月額として入れると、36回になること）
- 年率0%（月額 = 元本 ÷ 回数）
- 年率の既定値が、アプリを再起動しても保持されること（「既定にする」を押したときだけ更新されること）
- ボーナスあり（年2回、月を指定）で、残高が最終回でちょうど0になること
- 完済不能な条件でエラーになること

---

## 12. 開発の進め方（Claude Code向け）

1. 計算ロジックとユニットテストを先に作り、テストを通す
2. 入力画面と結果画面（利息のブラインド含む）を作る
3. 設定の読み書きと、設定画面を作る
4. HTMLテンプレートの差し込みとPDF出力を作る
5. 実際のテンプレートで印刷・PDFの見た目を確認して調整する
6. iPad向けのレイアウトと、iPadでのPDF出力・設定の取り込みを確認する（コードは最初から共通化しておく）

重要な決めごと（元利均等、端数処理、利息の非表示ルール）は、`CLAUDE.md` にも転記しておく。

- 実際に案内する分割条件は、信販会社などの計算方法（手数料率表など）と一致するか。一致しない場合は、アプリの数字を「目安」とする注記を必ず入れる
- 端数処理の既定値（切り捨てでよいか）
- 対象macOSのバージョン
- 別のMacへ配布する場合の対応（署名・公証など）。自分のMacだけで使うなら不要
- MacとiPadの間で、設定・テンプレートを自動同期（iCloud）する必要があるか。初期はエクスポート／インポートで足りるか
- 将来の拡張（履歴保存など）の要否
